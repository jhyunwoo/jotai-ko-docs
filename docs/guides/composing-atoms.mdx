라이브러리가 제공하는 `atom` 함수는 아주 원초적인 수준의 도구이지만,
동시에 매우 유연해서 여러 atom을 조합해 하나의 기능을 구현할 수 있습니다.

> 다시 한 번 강조하지만, `atom()`은 atom의 동작을 정의하는 객체인 atom config를 생성합니다.

atom을 어떻게 파생할 수 있는지 다시 정리해 보겠습니다.

### 기본 파생 원자

다음은 파생 atom의 가장 단순한 예 중 하나입니다.

```js
export const textAtom = atom('hello')
export const textLenAtom = atom((get) => get(textAtom).length)
```

`textLenAtom`은 read-only atom이라고 부릅니다.
`write` 함수가 정의되어 있지 않기 때문입니다.

다음은 `write` 함수를 사용하는 또 다른 단순한 예입니다.

```js
const textAtom = atom('hello')
export const textUpperCaseAtom = atom(
  (get) => get(textAtom).toUpperCase(),
  (_get, set, newText) => set(textAtom, newText),
)
```

이 경우 `textUpperCaseAtom`은 원래의 `textAtom` 값을 설정할 수 있습니다.
즉, `textUpperCaseAtom`만 export하고,
`textAtom`은 더 작은 스코프 안에 숨길 수 있습니다.

이제 몇 가지 실제 사례를 살펴보겠습니다.

### 기본 atom 값 덮어쓰기

read-only atom이 하나 있다고 가정해 봅시다.
물론 read-only atom은 직접 쓸 수 없지만, 두 개의 atom을 조합해서
그 read-only atom 값을 덮어쓰도록 만들 수는 있습니다.

```js
const rawNumberAtom = atom(10.1) // export해도 됩니다
const roundNumberAtom = atom((get) => Math.round(get(rawNumberAtom)))
const overwrittenAtom = atom(null)
export const numberAtom = atom(
  (get) => get(overwrittenAtom) ?? get(roundNumberAtom),
  (get, set, newValue) => {
    const nextValue =
      typeof newValue === 'function' ? newValue(get(numberAtom)) : newValue
    set(overwrittenAtom, nextValue)
  },
)
```

최종적인 `numberAtom`은 `atom(10)` 같은 일반적인 primitive atom처럼 동작합니다.
숫자 값을 넣으면 `overwrittenAtom` 값이 덮어써지고,
`null`을 넣으면 `roundNumberAtom` 값이 사용됩니다.

재사용 가능한 구현은 `jotai/utils`의 `atomWithDefault`로 제공됩니다.
[atomWithDefault](../utilities/resettable.mdx)를 참고하세요.

다음으로 외부 값과 동기화하는 또 다른 예를 살펴보겠습니다.

### atom 값을 외부 값과 동기화하기

우리가 다루고 싶은 외부 값들이 있습니다.
예를 들어 `localStorage`가 있고, 또 다른 예로 `window.title`이 있습니다.

`localStorage`와 동기화되는 atom을 만드는 방법을 보겠습니다.

```js
const baseAtom = atom(localStorage.getItem('mykey') || '')
export const persistedAtom = atom(
  (get) => get(baseAtom),
  (get, set, newValue) => {
    const nextValue =
      typeof newValue === 'function' ? newValue(get(baseAtom)) : newValue
    set(baseAtom, nextValue)
    localStorage.setItem('mykey', nextValue)
  },
)
```

`persistedAtom`은 primitive atom처럼 동작하지만,
그 값이 `localStorage`에 영속적으로 저장됩니다.

재사용 가능한 구현은 `jotai/utils`의 `atomWithStorage`로 제공됩니다.
[atomWithStorage](../utilities/storage.mdx)를 참고하세요.

이 사용법에는 주의할 점이 있습니다. atom config 자체는 값을 갖고 있지 않지만,
외부 값은 싱글턴 값입니다.
그래서 이 atom을 서로 다른 두 Provider에서 사용하면
두 `persistedAtom` 값 사이에 불일치가 생길 수 있습니다.
이 문제는 외부 값에 구독 메커니즘이 있으면 해결할 수 있습니다.

예를 들어 `jotai-valtio`의 `atomWithProxy`는 구독 기능을 함께 제공합니다.
그래서 이런 제한이 없습니다. 서로 다른 Provider에 있는 값도
동기화됩니다.

기본 주제로 돌아가서 또 다른 예를 살펴보겠습니다.

### `atomWith*` util로 atom 확장하기

이름이 `atomWith`로 시작하는 util이 여럿 있습니다.
이들은 특정 기능이 포함된 atom을 만들어 줍니다.
하지만 아쉽게도 두 개의 atom util을 곧바로 합칠 수는 없습니다.
예를 들어 `atomWithStorage`와 `atomWithReducer`를 함께 써서
하나의 atom을 바로 정의할 수는 없습니다.

이런 경우에는 직접 파생 atom을 만들어야 합니다.
`atomWithStorage`에 reducer 기능을 추가해 봅시다.

```js
const reducer = ...
const baseAtom = atomWithStorage('mykey', '')
export const derivedAtom = atom(
  (get) => get(baseAtom),
  (get, set, action) => {
    set(baseAtom, reducer(get(baseAtom), action))
  }
)
```

이 경우는 비교적 쉽습니다.
`atomWithReducer`가 `atomWithStorage`에 비해 단순한 구현이기 때문입니다.

더 복잡한 경우라면 그리 쉽지 않을 수 있습니다.
여전히 열려 있는 연구 주제에 가깝다고 볼 수 있습니다.

마지막으로 액션이 포함된 또 다른 예를 살펴보겠습니다.

### Action atom

이 패턴은 README에도 나와 있으니 익숙할 수 있습니다.
그래도 다시 한 번 짚어 보면 도움이 될 수 있습니다.

1씩만 증가하거나 감소할 수 있는 카운터를 만들어 보겠습니다.

한 가지 해법은 `atomWithReducer`입니다.

```js
const countAtom = atomWithReducer(0, (prev, action) => {
  if (action === 'INC') {
    return prev + 1
  }
  if (action === 'DEC') {
    return prev - 1
  }
  throw new Error('unknown action')
})
```

이 방식도 괜찮지만 아주 atomic하다고 보기는 어렵습니다.
코드 스플리팅이나 지연 로딩의 이점을 얻고 싶다면
write-only atom, 즉 action atom을 만드는 편이 좋습니다.

```js
const baseAtom = atom(0) // export하지 않습니다
export const countAtom = atom((get) => get(baseAtom)) // 읽기 전용
export const incAtom = atom(null, (_get, set) => {
  set(baseAtom, (prev) => prev + 1)
})
export const decAtom = atom(null, (_get, set) => {
  set(baseAtom, (prev) => prev - 1)
})
```

이쪽이 더 atomic하고, Jotai다운 방식처럼 보입니다.

다른 action atom을 호출하는 action atom도 만들 수 있습니다.

```js
// 이전 코드에서 이어짐
export const dispatchAtom = atom(null, (_get, set, action) => {
  if (action === 'INC') {
    set(incAtom)
  } else if (action === 'DEC') {
    set(decAtom)
  } else {
    throw new Error('unknown action')
  }
})
```

왜 이렇게 하고 싶을까요? 필요할 때에만 사용되기 때문입니다.
코드 스플리팅과 dead code elimination에 도움이 됩니다.

### 요약하면

atom은 빌딩 블록입니다.
다른 atom을 기반으로 atom을 조합함으로써
복잡한 로직을 구현할 수 있습니다.
이것은 read derived atom뿐 아니라 write action atom에도 해당합니다.

본질적으로 atom은 함수와 비슷하기 때문에,
atom을 조합하는 일은 함수를 다른 함수와 합성하는 것과 비슷합니다.

**참고**: atom에는 문자열, Blob, Observer 등 거의 어떤 종류의 데이터든 담을 수 있다고 말했습니다. 다만 예외가 하나 있습니다. 파생 atom은 함수로 정의되기 때문에, 순수 getter가 아닌 함수를 그대로 넘기면 Jotai는 그것을 이해하지 못합니다.
이럴 때는 함수를 객체로 한 번 감싸면 됩니다.

```js
const doublerAtom = atom({ callback: (n) => n * 2 })
// 사용법
const [doubler] = useAtom(doublerAtom)
const doubledValue = doubler.callback(50) // 100으로 계산됩니다
```
