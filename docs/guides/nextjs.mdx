### 하이드레이션

Jotai는 `useHydrateAtoms`로 원자의 수화를 지원합니다. 후크에 대한 문서는 [여기](../utilities/ssr.mdx)에서 볼 수 있습니다.

### 라우터와 동기화

라우터와 Jotai 동기화가 가능합니다. `atomWithHash`를 사용하여 이를 달성할 수 있습니다.

```js
const pageAtom = atomWithHash('page', 1, {
  replaceState: true,
  subscribe: (callback) => {
    Router.events.on('routeChangeComplete', callback)
    window.addEventListener('hashchange', callback)
    return () => {
      Router.events.off('routeChangeComplete', callback)
      window.removeEventListener('hashchange', callback)
    }
  },
})
```

이렇게 하면 구독하려는 항목을 [라우터 이벤트](https://nextjs.org/docs/api-reference/next/router#routerevents) 완벽하게 제어할 수 있습니다.

> #### Next.js 13에 관해
>
> Next.js 13부터 `Router.events.on()`에 변경이 생겨 더 이상 이벤트를 노출하지 않습니다. [앱 라우터 로드맵](https://beta.nextjs.org/docs/app-directory-roadmap#planned-features)에는 이벤트 차단과 해시 처리 계획이 포함되어 있지만, 언제 어떤 형태로 제공될지는 아직 알 수 없습니다. 현재는 `atomWithHash()`를 사용할 때 라우터 탐색만으로는 데이터가 들어 있는 atom을 다시 불러오지 못하고, 페이지를 새로고침하거나 컴포넌트가 다시 렌더링될 때만 반영됩니다. 또한 `setHash` 옵션은 `replaceState`로 설정하는 것이 좋습니다. Next.js는 내부적으로 `window.history`를 사용하므로 이렇게 하면 사용자가 브라우저의 뒤로 가기 버튼을 사용할 수 있습니다.

### 서버 측 렌더링에서는 약속을 반환할 수 없습니다.

SSR을 사용하면 Promise를 반환할 수 없다는 점을 기억하는 것이 중요합니다. 하지만 Atom 정의 내에서 Promise를 방지하는 것이 가능합니다.

가능하다면 `useHydrateAtoms`를 사용하여 서버의 값을 수화하세요.

```js
const postData = atom((get) => {
  const id = get(postId)
  if (isSSR || prefetchedPostData[id]) {
    return prefetchedPostData[id] || EMPTY_POST_DATA
  }
  return fetchData(id) // 약속을 반환
})
```

### Provider

기본적으로 Jotai는 원자 값을 추적하기 위해 암시적 전역 저장소를 사용합니다. 이를 "Provider-less" 모드라고 합니다. 이 글로벌 저장소는 활성 상태로 유지되고 여러 요청 간에 공유되어 버그 및 보안 위험이 발생할 수 있으므로 SSR 시나리오에서 문제가 됩니다.

스토어의 수명을 하나의 요청 범위로 제한하려면 앱 루트(또는 애플리케이션의 일부에만 Jotai를 사용하는 경우 하위 트리)에서 [Provider](../core/provider.mdx)를 사용해야 합니다.

```typescript
import { Provider } from 'jotai'

function App({ Component, pageProps }: AppProps) {
  return (
    <Provider>
      <Component {...pageProps} />
    </Provider>
  )
}
```

이 경우:

1. `Provider`는 전역 저장소 대신 하위 트리에 사용된 원자의 상태를 유지합니다.
2. `Provider`의 수명은 앱 자체와 동일하며 각 SSR 요청마다 앱이 다시 생성되므로 기본적으로 스토어 수명도 단일 요청으로 제한됩니다.
